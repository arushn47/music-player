# Windows release publishing

## Verified format and invocation

Installed/locked Tauri CLI: **2.12.3**; Rust Tauri: **2.12.4**; updater plugin: **2.14.0**. `src-tauri/tauri.release.conf.json` enables `bundle.createUpdaterArtifacts: true` only when explicitly supplied. Ordinary builds do not require signing keys.

For this v2 configuration the NSIS installer **is also the updater payload**:

- `Lumaire_1.0.4_x64-setup.exe`
- `Lumaire_1.0.4_x64-setup.exe.sig`
- `latest.json` (generated by the official action, not the bundler)

With the workflow's explicit target the first two files are under `src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`. The legacy `.nsis.zip` and `.nsis.zip.sig` are generated only with `createUpdaterArtifacts: "v1Compatible"`, which this app does not use. No ZIP is fabricated. Updater signing is separate from Authenticode; Windows can still show an unknown-publisher warning.

Sources checked against the installed CLI/schema and matching upstream tag:

- [Official artifact formats](https://v2.tauri.app/plugin/updater/#building)
- [CLI 2.12.3 signing logic](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.3/crates/tauri-cli/src/bundle.rs)
- [Legacy archive generation](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.3/crates/tauri-bundler/src/bundle/updater_bundle.rs)
- [Pinned official action source](https://github.com/tauri-apps/tauri-action/tree/84b9d35b5fc46c1e45415bdb6144030364f7ebc5)

`tauriScript: node scripts/tauri.mjs` makes the action execute:

```powershell
node scripts/tauri.mjs build --ci --bundles nsis --target x86_64-pc-windows-msvc --config src-tauri/tauri.release.conf.json -- --locked
```

The existing wrapper forwards `process.argv.slice(2)` unchanged to the project's installed CLI. On GitHub it uses the user Cargo binary and stable Rust, with `.tools/cargo` as Cargo home. It preserves signing environment variables. Direct Node invocation avoids npm separator ambiguity; the final `-- --locked` deliberately reaches Cargo. Tauri automatically merges the existing Windows configuration/installer hooks before the explicit release overlay.

## Workflow safeguards

The Windows 2022 runner supplies MSVC Build Tools, Windows SDK, WebView2 and GitHub CLI. Actions install Node 24, locked npm dependencies and stable Rust with the Windows x64 target. Tests run before packaging; Tauri's prebuild hook runs `npm run build`.

The workflow accepts version tag pushes or a manual dispatch for an **existing remote tag**. Tags must be stable `vMAJOR.MINOR.PATCH`, match npm/Tauri/Cargo versions, and resolve to the checked-out commit. Only the release job has `contents: write`; concurrent releases are serialized. Existing releases are rejected rather than overwritten.

The official action is pinned to inspected `v0` commit `84b9d35b5fc46c1e45415bdb6144030364f7ebc5`. It uploads the EXE, signature and `latest.json` to a draft. The workflow downloads those assets and verifies nonempty files, byte equality to the freshly built files, signature key identity, manifest version/date, complete signature contents and exact Windows payload URL. Only then does it publish and mark the release latest. Failed/incomplete drafts never replace the public update endpoint.

Endpoint: `https://github.com/arushn47/music-player/releases/latest/download/latest.json`

For v1.0.4, `platforms.windows-x86_64.url` must be `https://github.com/arushn47/music-player/releases/download/v1.0.4/Lumaire_1.0.4_x64-setup.exe`.

If a run fails after creating a draft, inspect it, remove that **unpublished** failed draft, then retry. Do not overwrite published signed assets; use a new version. Manual dispatch and tag pushes both publish after validation; dispatch is not a dry run.

## Secrets

The existing `TAURI_SIGNING_PRIVATE_KEY` and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` repository secrets are supplied only to the signing/preflight steps. The key secret must contain the complete private key contents, not a local path. Both must be nonempty; this workflow expects a password-protected release key. `GITHUB_TOKEN`/`GH_TOKEN` uses the automatic job token for release operations and is never embedded in the app. No command prints secrets or writes them into assets.

The existing `%USERPROFILE%\.lumaire-updater.key` was not accessed. Do not generate a replacement, commit it or lose its secure backup. The public key already configured in the app is preserved.

## First release — commands to run later

Review and commit the application/updater WIP **and** this release setup first. A tagged workflow builds committed files, never the local working tree. Many app files are currently modified/untracked. `.gitignore` explicitly allows these release documents and the status document while leaving other docs ignored.

Local checks without signing/publishing:

```powershell
$env:RELEASE_TAG = 'v1.0.4'
node scripts/check-windows-release.mjs
node --test scripts/check-windows-release.selfcheck.mjs
npm test
npm run tauri -- build --ci --bundles nsis --config src-tauri/tauri.release.conf.json --no-sign -- --locked
```

The final command smoke-tests packaging and intentionally creates no signature. Do not publish that unsigned result as an updater release.

After reviewing/committing and pushing the branch, choose **one** route. Keep version **1.0.4** for the initial bootstrap release only if it has not already been published; otherwise change versions in a separate task.

```powershell
# Route A: this tag push triggers the workflow.
git tag -a v1.0.4 -m 'Lumaire 1.0.4'
git push origin v1.0.4
```

```powershell
# Route B: dispatch for an existing remote tag; workflow must be on the default branch.
# Do not also trigger Route A for the same release.
gh workflow run windows-release.yml --repo arushn47/music-player --ref main -f tag=v1.0.4
```

Route B helps if the tag predates automatic triggering, but its commit must still contain this workflow's required config, validator and application code. Replace `main` if the default branch differs. Inspect the completed release with:

```powershell
gh release view v1.0.4 --repo arushn47/music-player
gh release download v1.0.4 --repo arushn47/music-player --pattern latest.json --dir .tools/release-inspection
```

Old 1.0.4 EXE/APK artifacts predate the updater. Windows users need the updater-enabled bootstrap installer manually. A later signed version must still prove actual update download, explicit restart and preserved library/settings. Until that installed-app upgrade succeeds, this is **not production-verified**. No tag, release, key or version increment was created during setup.
